## Middleware-authoring API (`REPLy.`-qualified)

[How-to: Building Custom REPLy Middleware](howto-custom-middleware.md) uses several symbols
that are **supported but intentionally not exported** — you must reach them with the
`REPLy.` prefix (e.g. `REPLy.handle_message`). Keeping them qualified avoids polluting your
namespace and signals that they are an extension seam rather than everyday API:

- `REPLy.AbstractMiddleware` — supertype your middleware subtypes
- `REPLy.handle_message` — the method you override; `(mw, msg, next, ctx::RequestContext)`
- `REPLy.emit!` — push a side-channel message from within a handler
- `REPLy.session_module` — the `Module` backing the active session
- `REPLy.default_middleware_stack` — the built-in ordered stack (build from this, don't
  replace it wholesale)

`MiddlewareDescriptor`, `descriptor`, `validate_stack`, and the `*Middleware` structs listed
above *are* exported. The [middleware how-to](howto-custom-middleware.md#Public-API-Reference)
lists the full authoring surface with signatures.
